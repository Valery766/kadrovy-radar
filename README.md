# Кадровый радар - от зарплаты до отклика в MAX

Хакатон MAX 2026, «Эффективный бизнес», команда unecon.tech.
Бот: https://max.ru/t796_hakaton_max_bot · приложение: https://radar.digital-projects.tech/app/.

**Статус 30.09.2026.** Версия 0.1.0, репозиторий https://github.com/Valery766/kadrovy-radar (архив исходников с контрольной суммой включён в комплект; точный коммит указан на служебном слайде презентации и в RELEASE.json).

Исправленная версия работает на публичном адресе, база перенесена на новый сервер без потерь. К MAX подключён ровно один обработчик в режиме webhook, прежний остановлен. В каталоге 150 учебных вакансий в 24 регионах: это подготовленный демонстрационный набор, помеченный в каждом объявлении. Ограничения проверки перечислены в разделе 14. Исторический README сохранён в docs/README-история-23.09.md.

## 1. Назначение решения

Владелец небольшого кафе, магазина или сервиса сам нанимает линейного сотрудника. Приоритетный путь: регион и должность → ориентир рынка → собственная зарплата → проверенный текст → отклик → ответ работодателя. Это прикладной инструмент найма, не универсальная HR-система и не копия hh.ru.

Рыночные объявления дают ориентир, не запрет на другую зарплату и не гарантию найма. Каталог содержит только вакансии, явно опубликованные работодателями нашего сервиса. Сокращение времени закрытия и потерь выручки - гипотеза, не доказанный результат пилота.

## 2. Основной пользовательский сценарий

1. /start → «Проверить ставку». Регион (ИНН необязателен), должность, текущая зарплата или «нет».
2. Карточка рынка с датой, выборкой и объяснением. Выбрать сумму кнопкой либо «Своя зарплата», например 83000. Допустима любая целая сумма 1 000-5 000 000 ₽ в месяц до НДФЛ.
3. Проверить черновик, изменить текст на реальные обязанности, график и место работы. По желанию включить каталог.
4. «Подтвердить публикацию» → ссылка и QR. Повтор не создаёт дубль; старые кнопки голосования выбирают сумму, а не голосуют.
5. Кандидат: /jobs/«Найти работу» без ИНН и QR либо ссылка вакансии → три вопроса → явное согласие на передачу данных. Телефон необязателен.
6. Работодатель: /vacancies/«Вакансии и отклики» → ответы → приглашение/отказ/найм. «Нанят» закрывает вакансию. Решение всегда принимает человек.

В приложении тот же процесс: поле своей зарплаты, редактируемый текст, подтверждение условий, отдельная отметка каталога. Без каталога вакансия остаётся доступна по ссылке/QR. PDF, подписки, штат, региональные расчёты и проверки - дополнительные функции, скрытые из основного пути.

## 3. Состав и архитектура

Один Node.js-процесс: Fastify API + обработчик MAX + React/Vite приложение + SQLite + фоновые задачи. Без LLM, брокера и отдельной БД. Nginx/HTTPS нужен только публичному live-стенду.

server/src/core - расчёты/шаблоны; adapters - источники; services - рынок/найм/отчёты; bot - диалог; api - сессии и права; db - записи/транзакции; packs - адаптируемые данные. webapp/src - интерфейс. Подпись initData MAX проверяется сервером; чужие отклики/контакты недоступны. Отклик и метрика сохраняются атомарно; повтор HTTP-публикации защищён requestId.

## 4. Одна команда Docker

Одна команда запускает все локальные компоненты решения:

```sh
cp .env.example .env && docker compose up --build -d --wait
```

`.env` нужен потому, что Compose читает его через `env_file`; готовый `.env.example` не содержит секретов и запускает сервис в режиме `MAX_UPDATES_MODE=none`.

Открыть http://localhost:8080/app/. Чистая сборка Linux amd64 / Node 24 с --no-cache 27.09.2026: **21,15 с**, базовый образ скачан заранее. Это замер конкретного сервера, не гарантия любой сети. Публичные сертификаты и шрифты включены; apt при сборке не нужен.

## 5. Необходимые параметры окружения

Docker с Compose; доступ к npm/Docker registry при сборке и открытым источникам для живых расчётов. .env.example использует MAX_UPDATES_MODE=none: токена не нужно, реальных сообщений нет.

Для MAX необходимы выданный токен, постоянные секреты, публичный HTTPS и привязка приложения организаторами. На токене должен работать ровно один обработчик: webhook и polling одновременно нельзя. Секреты - на сервере или в приватном канале технической проверки, не в публичном репозитории. SSH/HawkScan-ключи для проверки продукта не нужны.

## 6. Переменные окружения

| Переменная | Назначение |
|---|---|
| MAX_BOT_TOKEN, MAX_WEBHOOK_SECRET | Секрет бота и отдельный секрет входящего webhook |
| MAX_UPDATES_MODE | none / webhook / polling; один live-обработчик |
| SESSION_SECRET | Постоянный случайный секрет сессии для live |
| PUBLIC_URL, MAX_API_BASE | HTTPS live-адрес; API по умолчанию https://platform-api2.max.ru |
| PORT, HOST | Процесс; Compose задаёт 8080 и 0.0.0.0 |
| HOST_PORT, BIND_HOST | Порт хоста и адрес; по умолчанию 8080 / 127.0.0.1 |
| DATA_DIR, PACKS_DIR | Данные и пакеты; Compose: /data, /app/packs |
| TRUST_PROXY | Только адрес/CIDR доверенного прокси; не true на публичном хосте |
| NODE_EXTRA_CA_CERTS | Публичная цепочка MAX; Compose: /app/server/certs/russian_trusted_bundle.pem |
| LOG_LEVEL | info |
| VACANCY_CACHE_HOURS, PROFILE_CACHE_HOURS | Кэш рынка 6 ч, профиля 720 ч |
| MAX_VACANCY_RECORDS, MAX_EMPLOYERS_TO_ENRICH | Выборка до 2000, обогащение до 60 работодателей |
| ERKNM_YEAR, ERKNM_MAX_AGE_DAYS | Год дополнительного плана и свежесть 7 дней |

## 7. Используемые порты

Контейнер 8080, хост по умолчанию только 127.0.0.1:8080. Для live Nginx принимает 443 и проксирует localhost. BIND_HOST может намеренно открыть HTTP, но не заменяет HTTPS. SSH 22 - не часть продукта. 8094/8095 - только локальные инструменты UI/DAST.

## 8. Зависимости

Node 22.13 и новее (в образе Node 24), TypeScript, Fastify, @maxhub/max-bot-api, React/Vite/MAX UI, SQLite через Node, PDFKit, qrcode. Точные версии - package-lock.json, установка npm ci. Vitest для тестов. PT Sans с OFL включён. PEM здесь - публичные сертификаты, не приватные ключи. HawkScan - инструмент разработчика, для запуска не нужен.

## 9. Внешние сервисы и интеграции

MAX https://dev.max.ru/docs - сообщения, callback, файлы, initData, bridge. «Работа России» https://opendata.trudvsem.ru/api/v1 - рынок и справочник. ФНС https://rmsp.nalog.ru - необязательный профиль. ЕРКНМ https://proverki.gov.ru - дополнительный план проверок фоном. Закрытого API/платной модели нет.

MAX нельзя воспроизвести в контейнере: нужен реальный аккаунт/HTTPS/привязка. При сбое внешнего источника показываем дату кэша, малую выборку или ошибку, не подставляем вымышленные цифры. HTTP API мини-приложения доступен по https://radar.digital-projects.tech. Спецификация находится в openapi.yaml, обязательные проверки и роли - в DATA-API.yaml, тестовые примеры - в TEST-DATA.json. Защищённые действия используют сессию MAX; вход производится через POST /api/session с подписанными данными MAX. Общих паролей и административного входа в продукт нет.

## 10. Работа с данными

SQLite в томе stavka-data: пользователи/диалог, карточки, вакансии, отклики/статусы, кэши, подписки, профили и дополнительный план. Старые таблицы голосов сохранены для совместимости; новые голоса не пишутся. Старые вакансии не становятся публичными без решения владельца.

Имя MAX и ответы кандидата передаются выбранному работодателю после согласия. Контакт необязателен, подпись MAX проверяется. Каталог не раскрывает телефоны/ответы/внутренние карточки. Не пишите персональные данные в публичном объявлении. .env и производственная база не входят в архив.

Рынок - предложения, не фактические выплаты. Медиана, ограничения вклада работодателя и методика раскрыты в коде/карточке. SQLite резервировать согласованным backup/VACUUM INTO, не копированием одного живого WAL-файла. Импорт ЕРКНМ не удерживает транзакцию между асинхронными пачками и не откатывает чужие данные при ошибке.

## 11. Тестовые данные

Что здесь модельное, а что настоящее. Модельные данные: 150 учебных вакансий каталога с вымышленными работодателями (`tools/demo-catalog.json`, заливка `tools/seed-demo-catalog.mjs`), учебные отклики на 12 из них и синтетический стенд `tools/preview-jobs.mjs`. Интеграции с MAX, «Работой России», реестром МСП и ЕРКНМ настоящие и ничем не подменяются: если источник молчит, показываем дату кэша или ошибку.

/demo - явно обозначенный пример чужого публичного предприятия, профиль пользователя не меняется. Вне MAX - демо без права публикации/отклика/найма.

Для автономного UI: после npm ci/build выполнить PREVIEW_SCAN_MODE=1 PREVIEW_PORT=8095 node tools/preview-jobs.mjs. Синтетические работодатель/кандидат, явная маркировка страниц, внешние fetch запрещены, MAX-сообщений нет. Инструмент не импортируется production entrypoint.

## 12. Пошаговая проверка

1. npm ci; npm run typecheck; npm test; node --test tools/seed-demo-catalog.test.mjs; npm run build. 30.09.2026 прошли 163 теста приложения и отдельный тест сохранности реальных откликов при повторном импорте учебного каталога.
2. Подготовить .env и запустить Docker; /api/health → 200, /app/ → интерфейс.
3. После live-выкладки: /start → Санкт-Петербург → Повар/Водитель → текущая ставка/нет → карточка.
4. Своя зарплата 83000, редактирование, каталог, подтверждение. Сохраняется именно 83000, не медиана; повтор без дубля/голосования.
5. Кандидат (удобно с другого аккаунта MAX): /jobs → поиск по должности, региону и зарплате → карточка → три ответа, согласие → один отклик.
6. Работодатель: /vacancies → приглашение → проверить доставку второму аккаунту → Нанят → закрытие и запрет нового отклика.
7. Мобильный и веб-MAX обязательны. PDF и shareMaxContent проверять отдельно, если заявляем бонус. Локальный синтетический проход не заменяет live-проверку.

## 13. Ожидаемое поведение

83000 сохраняется независимо от медианы. 0/999/дробная HTTP-сумма/свыше 5 млн → понятная ошибка без записи. Вариант зарплаты открывает черновик, не счётчик голосов. Ошибка MAX не теряет отклик: он остаётся в инбоксе, доставка обозначается отдельно. Чужая карточка → 403/404, неверная подпись → 401, новая заявка закрытой вакансии → 409. После терминального решения нет повторного приглашения.

## 14. Известные ограничения

Каталог наполнен учебными вакансиями команды. Учебные отклики и три «найма» показывают работу кабинета и не являются результатами пилота. 30.09.2026 команда подтвердила работу бота с двумя реальными аккаунтами MAX. Отдельный протокол мобильного клиента пока не предоставлен. Экономию и сокращение срока найма предстоит измерить на пилоте. Кабинет возвращает до 500 собственных вакансий; общий каталог использует постраничную выдачу.

Динамическое сканирование 30.09.2026 на изолированном стенде: API (27 путей) - 0 High/Medium/Low, интерфейс (5 стартовых страниц) - 0 High/Medium и один Low. Low относится к официальному скрипту MAX https://st.max.ru/js/max-web-app.js; CSP ограничивает источник st.max.ru. Это остаточный риск стороннего SDK, не ложное срабатывание. Сканирование не покрывает webhook-транспорт, государственные источники и фактическую доставку сообщений MAX. `npm audit --omit=dev` 30.09.2026: 0 известных уязвимостей производственных зависимостей. Обезличенное подтверждение включено в конкурсный комплект. Это ограниченная проверка, не гарантия отсутствия любых уязвимостей.

Нет автоматической проверки человека, кадрового делопроизводства/трудового договора, гарантии найма. Один процесс/SQLite - сознательный MVP; при росте понадобится другая БД/очередь, сейчас это избыточно.

## 15. Остановка и повторный запуск

```sh
docker compose stop
docker compose start
docker compose logs --tail=100 app
docker compose up --build -d --wait
```

Том сохраняется при stop/down. Не использовать down -v: он удалит данные. При миграции сначала проверенная резервная копия, затем остановка только старого MAX-обработчика, перенос данных/секретов, HTTPS и проверка нового. Два webhook-watchdog одновременно не запускать. Другие проекты на старом сервере не трогать; старый deploy.sh не применять вслепую.
