# Сценарий демонстрации (5 минут) и вопросы жюри

## Демо (в MAX, с телефона или web.max.ru)
1. **0:00** Открываем `@t796_hakaton_max_bot` → «Начать». Одна фраза: «Кадровый радар: сколько платят конкуренты вашего размера, где ваша ставка на шкале рынка и как по этой ставке сразу нанять».
2. **0:30** «Проверить ставку» → бот просит ИНН → `7801633015` → профиль из реестра МСП: ООО «Малый 43», микропредприятие, ОКВЭД 56.10, Санкт-Петербург. Подчеркнуть бейдж «ФНС · получено сегодня».
3. **1:00** «Верно, дальше» → «Повар» → `45000` → карточка: 22-й перцентиль, медиана 65 000 ₽, микропредприятия — 80 000 ₽, выборка 258/234 из 702. Пояснить: дубли и объявления сверх лимита на работодателя убраны, размер работодателя — из реестра МСП.
4. **2:00** «Подробный разбор» → шкала, гистограмма, варианты ставки, категории работодателей, типичные вакансии, источники с датой.
5. **2:45** «Прислать PDF-отчёт» → PDF в чате → «Поделиться отчётом в MAX» → выбираем чат совладельца → отчёт переслан (бонус MAX).
6. **3:15** От цифры к действию: «Опубликовать на 65 000 ₽» → карточка вакансии с QR и ссылкой `?start=vac_…`. Со второго телефона открываем ссылку → «Откликнуться» → три вопроса → «Поделиться номером». В первом аккаунте: уведомление об отклике, `/vacancies` → инбокс → «Пригласить» (кандидату приходит сообщение).
7. **4:00** `/checks` → «Проверки 2026» по ИНН из плана ЕРКНМ: даты, вид надзора, орган, плюс контекст по региону и ОКВЭД. Подчеркнуть: только строки плана, никаких «вероятностей».
8. **4:30** Масштабирование: `/profile` → `1601000159` (Агрызское райпо, Татарстан, розница) → «Продавец» → `35000` — тот же код, другой пакет контекста. Показать `packs/tatarstan-roznitsa.yaml` и `git diff --stat` (ядро не тронуто).
9. **4:50** Резюме: три живых госисточника, детерминированный расчёт, честная выборка, найм закрыт внутри MAX.

В запасе, если спросят: `/staff` (кто из штата ниже рынка и цена выхода на медиану), `/regions` (одна должность по регионам с индексом доступности), `/digest` (сводка для партнёра), голосование по вариантам ставки и подписка «Следить за рынком».

## Вопросы, которых ждём
- **«Госпортал не весь рынок»** — да: показываем заявленные ставки и размер выборки; главная ценность — срез по размеру работодателя; следующий шаг — второй источник (hh.ru по договору).
- **«Медиана ниже реальной»** — поэтому даём распределение и «верхнюю четверть», а не одно число; наблюдаем закрытие вакансий выше/ниже медианы.
- **«Это калькулятор, который гуглится»** — за 10 минут на job-бордах не получить срез «микропредприятия vs бюджет» и распределение по 234 работодателям; у нас это 30 секунд в мессенджере плюс отчёт партнёру.
- **«Почему без LLM?»** — п. 9.5 правил и принцип кейса: факты/расчёты/рекомендации разделены, каждое число выводимо; LLM можно добавить как объяснительный слой, не как источник результата.
- **«Как масштабируется?»** — YAML-пакеты: регион 0 ч, отрасль 1 ч, источник 1–2 дня; универсальный пакет уже покрывает 91 регион, карта покрытия — `docs/coverage.md` (917 из 1365 пар «регион × профессия» дают выборку выше порога).
- **«Персональные данные?»** — ИНН ИП: храним только ИНН и публичные поля реестра, не логируем; отчёты только в личный чат пользователя. Номер кандидата появляется, лишь если он сам нажал «Поделиться номером» (подпись контакта MAX проверяем на сервере), и виден только работодателю этой вакансии.
- **«Что если API упадёт?»** — кэш 6 часов, деградация с пометкой даты, «Повторить» без перезапуска сценария; сторож вебхука; архив ЕРКНМ разбирается с диска, если сайт реестра недоступен.
- **«Почему отклики ранжируются?»** — это арифметика по правилам (опыт, график, разрыв ожиданий, наличие номера), формула в `docs/limitations.md`; кандидатов не отсеиваем, отклик виден целиком.
