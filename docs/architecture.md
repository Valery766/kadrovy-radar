# Архитектура «Кадрового радара»

```
 Пользователь MAX ──(чат)──► MAX Bot API ──webhook HTTPS:443──► server/src/bot/updates.ts
      │                                                            │ секрет, идемпотентность, 200 сразу
      │                                                            ▼
      │                                                    bot/scenario.ts (ИНН → должность → ставка)
      │                                                            │
      └──(мини-приложение, MAX Bridge initData)──► api/routes.ts ──┤
                                                     │ HMAC initData, сессия                 │
                                                     ▼                                       ▼
                                             services/market.ts  ◄──────────────────────────┘
                                             │ кэш (db) → trudvsem (страницы ×6) → rmsp (обогащение ИНН) → core
                                             │ services/staff.ts · regions.ts · region-digest.ts — те же карточки пачками по 3
                                             │ services/inspections.ts ◄── scheduler ──► erknm (ZIP плана проверок → SQLite)
                                             ▼
                                        core/market.ts  (чистые функции: normalize → dedupe → stats → seasonality → verdict)
                                        core/staff.ts · core/regions.ts (перцентиль штата, индекс доступности региона)
                                             │
                                             ▼
                                   карточка → чат (текст + кнопки) / JSON мини-приложению / PDF (report/pdf.ts)
                                             │                                      │
                                             │                      POST /uploads → POST /messages → mid → shareMaxContent
                                             ▼
                                   services/hiring.ts (вакансия из карточки → ссылка ?start=vac_<id> + QR → отклик кандидата → инбокс)
```

## Контур найма

Карточка рынка — не конец сценария: кнопка «Опубликовать на N ₽» превращает её в вакансию (`services/hiring.ts`,
`POST /api/cards/:id/vacancy`). Сервис берёт ставку из карточки (или присланную), текст — черновик ядра
(`core/vacancy-text.ts`) либо отредактированный пользователем, кладёт строку в `vacancies` и возвращает диплинк
`https://max.ru/<бот>?start=vac_<id>`; параллельно рисует QR (`qrcode`), грузит его через `POST /uploads` и присылает
работодателю карточку вакансии с кнопками «Поделиться в MAX», «Отклики», «Закрыть вакансию».

Кандидат приходит по диплинку: `bot_started` со `startPayload=vac_<id>` открывает объявление и кнопку «Откликнуться».
Дальше три вопроса кнопками (опыт → готовность к графику → ожидаемая ставка) и необязательный контакт: кнопка
`request_contact` MAX, подпись вложения проверяется на сервере (`phone_verified`). Отклик считается по правилам
(`scoreResponse`: совпадение опыта, готовность к графику, разрыв ожиданий и ставки, наличие номера) — никакой модели.
Работодатель получает уведомление в чат и видит инбокс: `/vacancies` в боте, экран «Вакансии и отклики» в
мини-приложении (диплинк `?startapp=inbox_<id>`), действия «Пригласить» / «Отказать» / «Нанят» пишут кандидату
сообщением от бота. Вакансия хранит `first_response_at` и `closed_at` — это метрики продукта (время до первого отклика
и срок закрытия), а не гипотезы.

## Плановые проверки (ЕРКНМ)

Третий источник живёт не в запросе пользователя, а в фоновой загрузке: набор открытых данных Генеральной прокуратуры — это годовой план контрольных (надзорных) мероприятий целиком (ZIP на 38,8 МБ, 809 XML, 29 644 КНМ на 2026 год), и дёргать его на каждый запрос бессмысленно. Планировщик через 20 секунд после старта (не блокируя запуск) берёт паспорт набора `GET /public/api/opendata/plans/{год}`, сравнивает имя архива с сохранённым в `inspection_datasets` и, если версия новая, скачивает архив в `DATA_DIR/erknm/`, разбирает его потоком — файл за файлом и КНМ за КНМ (драйвер `integrations/erknm.ts`: `yauzl` на распаковку, `fast-xml-parser` на блоки `<INSPECTION>`) — и перезаливает таблицу `inspections` одной короткой транзакцией через промежуточную таблицу. Пик памяти при разборе — около 60 МБ, полный проход — 14 секунд. Дальше задача просыпается раз в час, но к источнику идёт, только если набор не подтверждали больше `ERKNM_MAX_AGE_DAYS` (7 дней) — то есть проверка версии раз в неделю, а часовой шаг нужен для повтора, когда сайт реестра недоступен (он отвечал 502 при проверке 23.09.2026).

Запрос пользователя (`services/inspections.ts`, `GET /api/inspections`, `/checks` в боте, блок «Проверки» в мини-приложении) не ходит в сеть вовсе: плановые КНМ ищутся по ИНН (индекс `inn`), контекст — по `(region_code, okved2, kind)`. Вид надзора нормализуется в четыре группы (`labor` / `sanitary` / `fire` / `other`) по подстрокам `KIND_CONTROL`, исходная формулировка реестра сохраняется и показывается как есть. Регион записи берётся из адреса объекта контроля сопоставлением с названиями субъектов из `packs/_shared/regions.json`; не определился — `null`. Пока набор не загружен, сервис отвечает `loaded: false` («данные ещё не загружены»), а не ошибкой. Ядро (`core/`) об этом источнике по-прежнему ничего не знает.

## Ядро и переменная часть

| Ядро (`server/src/core`, `webapp/`) | Переменная часть (`packs/`) |
|---|---|
| модель данных (VacancyRecord, EmployerProfile, MarketCard) | регион (код ФНС, название) |
| нормализация названий, дедупликация, квантили, гистограмма | отрасль (префиксы ОКВЭД) |
| вердикт и варианты ставки | список профессий, синонимы, исключения |
| частотный разбор требований | словарь формулировок требований |
| оценка штата (`core/staff.ts`), сравнение регионов (`core/regions.ts`), сезонность (`core/seasonality.ts`) | справочник ОКПДТР для подсказок (`_shared/okpdtr.json`) |
| черновик вакансии | пороги достоверности, шаблон условий |
| сценарий бота и экраны мини-приложения | демо-пример |

Ядро не импортирует ничего из `integrations/`, `bot/`, `api/` и не содержит строковых констант с названиями регионов, отраслей или профессий. Переключение контекста — выбор пакета по профилю бизнеса (`packs/loader.ts: selectPack`): регион + отрасль → регион → универсальный.

## Тиражирование

| Контекст | Без изменений | Адаптируется | Данные и интеграции | Трудоёмкость |
|---|---|---|---|---|
| Другой регион (любой из 91) | всё | ничего: универсальный пакет берёт регион из профиля | те же два источника | 0 |
| Любая должность вне каталога | всё | ничего: `resolveProfession` собирает профессию `custom:<slug>` из текста, подсказки — по локальному ОКПДТР (8 037 позиций) | те же | 0 |
| Новая отрасль в регионе (например, автосервисы 45.20) | ядро, бот, приложение | один YAML: профессии, синонимы, условия | те же | ~1 час |
| Сезонная отрасль (АПК: `packs/apk-sezon.yaml`, ОКВЭД 01, Краснодарский край) | ядро, бот, приложение | один YAML + профессии сезона в `_shared/professions.yaml`; неделя пика набора считается ядром из дат публикации | те же | ~1 час |
| Сравнение регионов и сводка для партнёра | ядро, пакеты | ничего: `services/regions.ts` и `services/region-digest.ts` работают по любому набору кодов ФНС и ключей профессий | те же | 0 |
| Другой источник вакансий (hh.ru API, Авито при наличии договора) | ядро, пакеты | драйвер в `integrations/` с тем же интерфейсом | новый источник | 1–2 дня |
| План проверок на следующий год | всё | ничего: `ERKNM_YEAR` (по умолчанию текущий год) | тот же набор ЕРКНМ | 0 |
| Другая страна | ядро | драйверы источников и справочники | другие реестры | недели |

Риски: изменение формата Open API «Работы России» (драйвер изолирован, тесты на фикстуре); ограничение доступа к реестру МСП (кэш 30 дней, деградация до режима «без профиля»); смещённость государственного портала (прозрачно показываем выборку; следующий шаг — второй источник вакансий).

## Надёжность

- Вебхук отвечает 200 до обработки; MAX доставляет событие до 10 раз — дедупликация по ключу события в `updates_seen`.
- Сторож переподписывает вебхук каждые 10 минут (MAX отписывает бота через 8 часов без ответа 200).
- Внешние HTTP-запросы: таймауты, повторы на 5xx/429, лечение невалидного JSON; при недоступности источника — последний кэш с датой.
- Ошибки сценария не роняют бота: пользователь получает сообщение и кнопку «Повторить», состояние диалога хранится в БД.
- Лимиты MAX (30 rps, 2 сообщения в секунду на чат) не превышаются: бот отправляет 1–2 сообщения на действие с паузой 600 мс, длинные тексты режутся по границам строк (лимит сообщения 4 000 символов).
- Веб-клиент MAX иногда шлёт `bot_started` дважды за одно открытие ссылки: повтор с тем же payload в течение 90 секунд игнорируется, второго приветствия не будет.
- Тяжёлые расчёты (карточка, штат, сравнение регионов, сводка) ограничены на входе в API: 6 запросов в минуту на сессию (3 в демо-режиме) → 429, и 4 одновременных расчёта на процесс → 503. Оба ответа — с человеческим текстом и без сброса сценария. Внутри расчёта обращения к источнику идут пачками по три (`services/pool.ts`), ошибка одного элемента не роняет остальные.
- Кэш вакансий живёт 6 часов (`VACANCY_CACHE_HOURS`), профиль реестра МСП — 30 суток: повторный проход сценария отвечает мгновенно и не нагружает госисточники.
- Свободный ввод должности не требует кода под каждую профессию: `resolveProfession` собирает ключ `custom:<slug>` детерминированно из текста, поэтому кэш и подписки по одному и тому же названию не дублируются.

## Безопасность

- Токен бота и секрет вебхука — только в `.env` на сервере; в репозитории `.env.example` без значений.
- `X-Max-Bot-Api-Secret` сравнивается за постоянное время; неверный секрет → 404.
- `initData` проверяется по официальному алгоритму (HMAC-SHA256 c ключом `WebAppData`), `auth_date` не старше часа; сессия — подписанный токен на 12 часов; `initDataUnsafe` на сервере не используется.
- Идентификаторы карточек, отчётов и вакансий — UUID v4; персональные данные не логируются; исходящие запросы только к заранее известным хостам.
- Карточка, отчёт, вакансия и отклики принадлежат владельцу: сервер сверяет `max_user_id` сессии и отвечает 403 чужому. Номер кандидата видит только работодатель этой вакансии.
- Зависимости зафиксированы `package-lock.json`, базовый образ закреплён (`node:24-bookworm-slim`).
