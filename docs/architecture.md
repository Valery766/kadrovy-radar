```
 Пользователь MAX ──(чат)──► MAX Bot API ──webhook HTTPS:443──► server/src/bot/updates.ts
      │                                                            │ секрет, идемпотентность, 200 сразу
      │                                                            ▼
      │                                                    bot/scenario.ts (ИНН → должность → ставка)
      │                                                            │
      └──(мини-приложение, MAX Bridge initData)──► api/routes.ts ──┤
                                                     │ HMAC initData, сессия                 │
                                                     ▼                                       ▼
                                             services/market.ts  ◄──────────────────────────┘
                                             │ кэш (db) → trudvsem (страницы ×6) → rmsp (обогащение ИНН) → core
                                             │ services/staff.ts · regions.ts · region-digest.ts — те же карточки пачками по 3
                                             ▼
                                        core/market.ts  (чистые функции: normalize → dedupe → stats → seasonality → verdict)
                                        core/staff.ts · core/regions.ts (перцентиль штата, индекс доступности региона)
                                             │
                                             ▼

                                                                                    │
                                                                    POST /uploads → POST /messages → mid → shareMaxContent
```

## Ядро и переменная часть

| Ядро (`server/src/core`, `webapp/`) | Переменная часть (`packs/`) |
|---|---|
| модель данных (VacancyRecord, EmployerProfile, MarketCard) | регион (код ФНС, название) |
| нормализация названий, дедупликация, квантили, гистограмма | отрасль (префиксы ОКВЭД) |
| вердикт и варианты ставки | список профессий, синонимы, исключения |
| частотный разбор требований | словарь формулировок требований |
| оценка штата (`core/staff.ts`), сравнение регионов (`core/regions.ts`), сезонность (`core/seasonality.ts`) | справочник ОКПДТР для подсказок (`_shared/okpdtr.json`) |
| черновик вакансии | пороги достоверности, шаблон условий |
| сценарий бота и экраны мини-приложения | демо-пример |

Ядро не импортирует ничего из `integrations/`, `bot/`, `api/` и не содержит строковых констант с названиями регионов, отраслей или профессий. Переключение контекста — выбор пакета по профилю бизнеса (`packs/loader.ts: selectPack`): регион + отрасль → регион → универсальный.

## Тиражирование

| Контекст | Без изменений | Адаптируется | Данные и интеграции | Трудоёмкость |
|---|---|---|---|---|
| Другой регион (любой из 91) | всё | ничего: универсальный пакет берёт регион из профиля | те же два источника | 0 |
| Любая должность вне каталога | всё | ничего: `resolveProfession` собирает профессию `custom:<slug>` из текста, подсказки — по локальному ОКПДТР (8 037 позиций) | те же | 0 |
| Новая отрасль в регионе (например, автосервисы 45.20) | ядро, бот, приложение | один YAML: профессии, синонимы, условия | те же | ~1 час |
| Сезонная отрасль (АПК: `packs/apk-sezon.yaml`, ОКВЭД 01, Краснодарский край) | ядро, бот, приложение | один YAML + профессии сезона в `_shared/professions.yaml`; неделя пика набора считается ядром из дат публикации | те же | ~1 час |
| Сравнение регионов и сводка для партнёра | ядро, пакеты | ничего: `services/regions.ts` и `services/region-digest.ts` работают по любому набору кодов ФНС и ключей профессий | те же | 0 |
| Другой источник вакансий (hh.ru API, Авито при наличии договора) | ядро, пакеты | драйвер в `integrations/` с тем же интерфейсом | новый источник | 1–2 дня |
| Другая страна | ядро | драйверы источников и справочники | другие реестры | недели |

Риски: изменение формата Open API «Работы России» (драйвер изолирован, тесты на фикстуре); ограничение доступа к реестру МСП (кэш 30 дней, деградация до режима «без профиля»); смещённость государственного портала (прозрачно показываем выборку; следующий шаг — второй источник вакансий).

## Надёжность

- Вебхук отвечает 200 до обработки; MAX доставляет событие до 10 раз — дедупликация по ключу события в `updates_seen`.
- Сторож переподписывает вебхук каждые 10 минут (MAX отписывает бота через 8 часов без ответа 200).
- Внешние HTTP-запросы: таймауты, повторы на 5xx/429, лечение невалидного JSON; при недоступности источника — последний кэш с датой.
- Ошибки сценария не роняют бота: пользователь получает сообщение и кнопку «Повторить», состояние диалога хранится в БД.
- Лимиты MAX (30 rps, 2 сообщения в секунду на чат) не превышаются: бот отправляет 1–2 сообщения на действие.

## Безопасность

- Токен бота и секрет вебхука — только в `.env` на сервере; в репозитории `.env.example` без значений.
- `X-Max-Bot-Api-Secret` сравнивается за постоянное время; неверный секрет → 404.
- `initData` проверяется по официальному алгоритму (HMAC-SHA256 c ключом `WebAppData`), `auth_date` не старше часа; сессия — подписанный токен на 12 часов; `initDataUnsafe` на сервере не используется.
- Идентификаторы карточек и отчётов — UUID v4; персональные данные не логируются; исходящие запросы только к заранее известным хостам.
- Зависимости зафиксированы `package-lock.json`, базовый образ закреплён (`node:24-bookworm-slim`).
