# План презентации «Ставка» (PDF, 12–14 слайдов)

Структура — по стр. 10 ТЗ. Первый слайд служебный, не оценивается.

1. **Служебный слайд (техническая информация)**: ссылка на бота `https://max.ru/t796_hakaton_max_bot`; мини-приложение `https://stavka.i-tech.unecon.ru/app/`; Git-репозиторий + commit hash; собственного API нет (внутренний HTTP между мини-приложением и сервером не заявляется); тестовые логины не нужны; рабочие переменные окружения (MAX_BOT_TOKEN, MAX_WEBHOOK_SECRET, MAX_UPDATES_MODE, PUBLIC_URL — значения только в этой версии PDF); краткий порядок сценария (7 шагов из README §12).
2. **Название и команда**: «Ставка — зарплатный радар для малого бизнеса в MAX». unecon.tech (СПбГЭУ): Черевко Валерий — капитан, архитектура и бэкенд; Бережных Михаил — фронтенд и дизайн; Частикова Анастасия — продукт и исследование; Шакирьянова Суфия — UX/UI и презентация (уточнить роли у команды).
3. **Executive summary**: одно предложение про продукт; три числа с живой демонстрации (повар, СПб: медиана 65 000 ₽, микропредприятия 80 000 ₽, ставка 45 000 ₽ = 22-й перцентиль); два настоящих госисточника; детерминированное ядро; бонус MAX — пересылка отчёта через shareMaxContent.
4. **Целевая аудитория и сегмент**: владелец/управляющий 1–5 точек общепита, розницы, услуг, нанимает линейный персонал сам (три оси: отрасль, масштаб, ситуация «уволился сотрудник — смена под угрозой»). Размер: 6,77 млн субъектов МСП, 96 % микро (реестр ФНС 10.09.2026), 15,1 млн работников; дефицит 1,8 млн работников (Росстат, май 2026); RSBI «Кадры» 44,2 — минимум за 6 лет.
5. **Проблема и актуальность**: формула ТЗ; As Is (8–12 вкладок, 40 минут, нет сравнения с похожими работодателями) → To Be (ИНН + должность + ставка → карточка за 30 с). Подтверждение данными: цена ошибки видна в данных (45 000 ₽ = 79 % платят больше). Интервью (добавить после проведения).
6. **Решение и основной сценарий**: 7 шагов с реальными скриншотами бота (web.max.ru) и мини-приложения; что делает бот, что мини-приложение (по рекомендации ТЗ стр. 15).
7. **Ожидаемый эффект и метрики**: время до решения о ставке (40 мин → 1 мин), число ручных действий, доля вакансий с рыночной ставкой, срок закрытия вакансии; метрика честности — доля карточек «данных мало»; гипотеза по формуле ТЗ стр. 17.
8. **Архитектура**: схема из docs/architecture.md; вебхук 443, идемпотентность, HMAC initData, SQLite, один контейнер; ядро/переменная часть.
9. **Данные и интеграции**: таблица источников (реальные, без модельных), метод расчёта (факт/расчёт/рекомендация), бейджи с датой; подводные камни API (offset = страница, потолок 10 000, невалидный JSON, 88 % дублей) и как обработаны.
10. **Возможность MAX сверх минимума (бонус)**: PDF → POST /uploads → POST /messages → mid → shareMaxContent → отчёт в любом чате; диплинк ?startapp=card_<id> с восстановлением карточки; подписка на сдвиг рынка; голосование по ставке в чате.
11. **Масштабирование**: ядро/переменная часть дословно по стр. 19 ТЗ; таблица тиражирования (регион 0 ч, отрасль 1 ч, источник 1–2 дня); демо двух пакетов (СПб общепит → Татарстан розница) без изменения кода; карта покрытия (регион × профессия); риски и условия адаптации.
12. **Пилот и внедрение (задел на финал)**: первый регион — Татарстан (финал в Казани) или СПб; канал доступа — ссылка на бота из МСП.РФ/центров «Мой бизнес»; партнёры; метрики пилота; следующий шаг — второй источник вакансий.
13. **Ограничения, риски, допущения, Won't Have**: заявленные ставки ≠ выплаты; смещение госпортала; латентность; охват профессий; не делаем: воронку кандидатов, парсинг коммерческих job-бордов, LLM в ядре, ФОТ/налоги.
14. **Источники**: ТЗ, dev.max.ru, opendata.trudvsem.ru, rmsp.nalog.ru, Росстат/Роструд, ЦБ (обеспеченность −19,7 п.), RSBI, hh.индекс.
